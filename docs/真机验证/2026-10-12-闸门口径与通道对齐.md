# 闸门口径与轴向通道对齐（2026-10-12）

起因：用户问"位移闸门 50mm 是从哪里取得的数据"。追溯下来，两个闸门（位移 / 荷载）都不该写死，
而且顺带查出**轴向通道读错了**。

## 1. 那个 50mm 的出处：没有出处

`git log -S "MaxDisplacementMM"` → 由 `8c58e19`（2026-10-10「M3 标签制报表 + 控制引擎与模拟器」）引入，
`461d790` 又在 `BendingExecution.Profile` 里显式写了一遍；两次提交说明都没引用规范或现役常量。
看当时的 diff：`MaxLoadKN = 50.0` 与 `MaxDisplacementMM = 50.0` 是挨着写的 —— **50 本是荷载的缺省值，
被顺手复制到了位移上**。

现役的真正口径（`TestThreads\AsphaltBendingTestThreadUnit.pas` 297-302 行）：

```pascal
LDispLimit := FDataController.AxialDisplacementScale;   // 优先：设备上报的位移通道量程
if LDispLimit <= 0 then LDispLimit := MAX_DEF_LIMIT_MM;  // 回落常量 20.0
LLoadLimit := FDataController.AxialPressureScale;        // 优先：设备上报的压力通道量程
if LLoadLimit <= 0 then LLoadLimit := MAX_LOAD_LIMIT_KN; // 回落常量 50.0
```

所以现役**两个闸门都以设备量程为准**，常量只是取不到时的兜底。我们的 50 恰好等于现役的**荷载兜底常量**。

## 2. 顺带查出的错：轴向压力通道读错了

真机 A0H 的压力通道量程 = `[100000, 5000, 0, 0]`、位移 = `[25000, 25000, 0, 0]`（小数位都是 3）：

| 通道 | 量程 |
| --- | --- |
| 压力通道 1（索引 0） | **100.000 kN**（主传感器） |
| 压力通道 2（索引 1） | 5.000 kN（小量程） |

现役生产库 `TestParameterConfig`（只读副本查询）里，**弯曲（`AsphaltTestTypeID = 5`）等所有配置行都是
`AxialPressureChannel = 0`** —— 即压力通道 1 = 100kN 主传感器；`HorizontalDisplacementChannel = -1` 表示不用。
而 ANX 此前硬编码 `pressChannelIndex = 1`，读的是 **5kN 小量程通道** —— 弯曲破坏荷载只有几 kN，
读数看着合理，所以一直没暴露。已改为索引 0（真机复测：荷载读数由 −0.027kN 变为 **−0.187kN**，即换到主传感器）。

## 3. 最终口径（用户 2026-10-12 确认）

| 闸门 | 算法 | 取不到设备量程时 |
| --- | --- | --- |
| 位移 | 设备位移量程 × 系数（默认 **0.95**；真机 25.000 → **23.75mm**） | 保持原值（不放开） |
| 荷载 | 设备压力量程 × 系数（默认 **0.95**；真机 100.000 → **95kN**） | 回落现役常量 **50kN** |

两个系数都进了参数表（机器参数组）：`DisplacementSafetyFactor` / `LoadSafetyFactor`，
运行前由 `BendingExecution.LoadProfileAsync()` 装配、执行页按设备量程算出实际闸门并写进操控信息。
取值都夹在 0.1~1.0（>1 等于放开保护）。

真机复测（只读）：`设备上报量程：压力 100 kN（通道 1）   位移 25 mm（通道 2）` ✓

## 4. 仍未对齐 / 待确认

1. **双位移传感器**：现役弯曲配置 `AxialDisplacementChannel = 8` → 统一通道 6+7，即**位移通道 1+2 取平均**
   （`EnableDualSensors = 1`）；ANX 现在只读位移通道 2。用户已说明"位移数值不准确由他人负责调整"，
   故本期不动，但**这是两边位移读数差异的一个可能来源**。
2. **试验速率**：现役生产库里弯曲的 `MachineSpeed = 5`（规范 50±5，现役线程的 `SPEC_LOAD_SPEED_MM_MIN = 50`
   只是兜底）；ANX 参数表默认 50。用户 2026-10-12 明确"**按规范要求设置**"，见下一节。

## 5. 试验速率：按规范设置（用户 2026-10-12 明确）

**口径：试验速率取规范值 —— T 0715 为 50 mm/min（现役线程注释引作"规定加载速率 50mm/min±5mm/min"），
不跟随现役生产库里的 `MachineSpeed = 5`。** ANX 参数表 `LoadRate` 默认已是 `50`，无需改动。

核对时的两点现场事实：

- 规范 PDF（`E:\规范文档\...弯曲试验.pdf` 与 617 页的总规程）**都是扫描件、没有文字层**
  （抽页 `get_text()` 字符数为 0），速率值没法直接从 PDF 里检索，只能用现役注释所引的规范值 + 用户确认。
- 现役线程的速率常量只是兜底：`SPEC_LOAD_SPEED_MM_MIN = 50`，参数表 `MachineSpeed > 0` 时以参数表为准 ——
  现场库里那条是 5，属现场配置行为，不是规范值。

## 6. 顺带修掉的 bug：运行中改速率不重发 C4 → 提速不生效

协议语义（用户 2026-10-10 给的 C4 说明）：**同向运转时，只有再发一次电机指令才会改速度**。
现役 `SetVelocityCmd` 每次调用都 `SendC4AndWait`，所以它"接触后提速"有效；而 ANX 的 `SetSpeedAsync`
此前**只改本地字段、不发帧** —— 接触成立后"切到试验速率"实际不生效，整轮都按接近速率（10mm/min）跑。

修法：`Gr3DeviceController.SetSpeedAsync` 改成"记速率 + **若电机正在运转且速率有变化，按当前方向重发 C4**"
（没在转就不发，速率留在字段里等 Start/Jog 带上）。同一语义在现役 `AsphaltBendingTestThreadUnit.pas` 里
是 `tpContact` 发 10 → `tpTesting` 发 `LTestSpeed`。

**真机验证（新加的 `--speed-change` 实验）**：按试验路径启动（C1 + C4 带 5mm/min）跑 4 秒 → **不停机**
只把速率改成 50mm/min 再跑 4 秒：

| 段 | 请求 | 实测 |
| --- | --- | --- |
| 第一段 | 5 mm/min | **6.27 mm/min** |
| 第二段（运行中改） | 50 mm/min | **58.65 mm/min**（≈9.4 倍） |

即改速率立即生效；修复前第二段会停在 5~6 mm/min。

## 7. 换向必须"先停后转"（用户 2026-10-12 明确要求）

需求原话："**电机运动换向时，先发电机停止命令，再发送电机启动命令**"。

落法：在控制器里做成**单一出口** `SendMotorAsync(order, speed)` —— 所有发 C4 的路径
（点动 / 启动 / 改速率重发 / 停止）都走它；当"新方向 ≠ 当前运转方向"且两者都不是 0 时，
先发停止（方向字 0）、等 `DirectionChangeSettleDelay`（默认 **500ms**）、再发新方向。
调用方（界面从"按住上升"改按"下降"、复位后重新启动…）不需要记得这件事。
当前方向优先取机器状态位（Bit3 正转 / Bit4 反转，设备是权威），取不到时回落到"最近一条命令"。

**真机验证（新加的 `--reverse-test` 实验）**：正转上升 2 秒后**不停机**直接发反转下降，
每 100ms 采样机器状态位：

```
0.1s  机器 0x08（正转=True 反转=False）   位移 0.182 mm
2.1s  机器 0x00（正转=False 反转=False）  位移 2.021 mm   ← 换向前的停止
2.6s  机器 0x10（正转=False 反转=True）   位移 2.030 mm   ← 500ms 后启动反转
4.4s  机器 0x00                          位移 0.596 mm
```

0x00 那段正好 500ms，与设置一致 ✓。用例 `换向时应先发停止再发启动` 断言帧序
（上升 → 上升不插停止；上升 → 下降为 `[1,0,2]`；反转中启动为 `[2,0,1]`；停止指令自身不再插停止）。

注：探针第一次跑这个实验时**看不到 0x00 段** —— 因为采样循环被 `await controller.JogAsync(Down)`
挡住了，正好错过换向那几百毫秒；改成"换向发在后台任务里、主循环继续采样"才看到。
