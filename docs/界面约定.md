> 记录用户明确提出的界面规则，**新增界面时照做**。每条都注明来源日期。

## 按钮（用户 2026-10-12）

1. **一律用主样式**：`Appearance="Primary"`，与执行页的「启动试验」一致；不要用 `Secondary`。
2. **一律配图标**：`Icon="{ui:SymbolIcon <Name>24}"`。已用到的对应关系：

   | 按钮 | 图标 |
   | --- | --- |
   | 启动试验 / 停止试验 | `Play24` / `Stop24`（随运行状态切换） |
   | 有效性计算 | `CheckmarkCircle24` |
   | 新建试验 / 新建试样 | `Add24` |
   | 编辑试样 | `Edit24` |
   | 删除试样 | `Delete24` |
   | 试验参数 | `Settings24` |
   | 打印报表 | `Print24` |
   | 历史数据 | `History24` |
   | 清空信息 | `Broom24` |
   | 数据流（占位，未实现） | `DataTrending24` |

3. **图标名先验证再写**：WPF-UI 的图标是 `SymbolRegular` 枚举，名字写错运行期不会报错、只是**静默没有图标**。用下面这条命令确认（示例查 Play24）：

   ```powershell
   rg -a -o -N "Play24" "C:\Users\ChenJie\.nuget\packages\wpf-ui\4.3.0\lib\net10.0-windows7.0\Wpf.Ui.dll"
   ```

   路径里的版本号取自当前引用的 WPF-UI 包版本。
4. **按钮内容是复合元素时补 `AutomationProperties.Name`**：把按钮内容换成 `StackPanel`（图标 + 文字）后，WPF 默认的自动化名称取不到文字，UIA 与读屏都会失明。示例（启动/停止按钮）：

   ```xml
   AutomationProperties.Name="{Binding ViewModel.StartStopText, Mode=OneWay}"
   ```

5. 未实现的占位按钮保持 `IsEnabled="False"` 并给 `ToolTip`（外观同样用主样式，禁用态自带变灰）。

## 数值卡（用户 2026-10-12）

- **峰值**：进页面、手动升降、接触前的空走都不显示（`—`）；点「启动试验」立即清零；**接触成立后**才开始累计；一轮结束保留最后一轮的值。
- **试验持续时间**：接触成立**才开始显示并计时**；接触前保持 `—`（点启动后不会立刻走表）。设备侧的内部计时一直在走 —— 接触搜索 300s 超时要用它。
- 两者共用 `TestExecutionViewModel._contactEstablished`：点启动置 false、接触成立置 true、一轮收尾置回 false（数值保留显示、不再被空闲读数改写）。

## 列表与页面滚动（用户 2026-10-12）

- **滚动只发生在页内列表上，页面本身不滚**。页面宿（WPF-UI 的 `DynamicScrollViewer`）按**无限高度**量内容，
  页内 Grid 的 `*` 行会退化成"按内容取高"——列表条目一多就把整页撑高，滚动落到外层宿主上。
- 对策：页面构造函数末尾调用 `PageViewportFitter.Attach(this);`
  （`Views\PageViewportFitter.cs`）——它把页面 `MaxHeight` 对齐到外层滚动容器的视口高度，
  `*` 行于是拿到真实可见高度，列表在页内自己滚。**凡是页内有 `*` 行 + 列表的新页面都要加这一句。**
  已加：试验执行页、试验单页、历史数据页。
- 列表**不要靠"刷新"按钮才加载**：切到该模式 / 进页面时自动查询（现役 `TSelectBendingTestMainForm.FormCreate`
  同样打开窗体即 `qryGetSheetInfo.Open`）；「刷新列表」只当手动再查用。
  已做：试验单页（切到「选择已有」即查）、**历史数据页（进页面即查，2026-10-13 用户提出）**、
  参数配置页 / 试样信息页（`OnNavigatedTo` 重新读库）。做法统一：`ViewModelBase.OnNavigatedTo()` 里发起查询。
- **试验单列表按创建时间倒序**（最新在最上，用户 2026-10-13 要求）：排序落在数据层
  `TestSheetService.QueryAsync` 的 `ORDER BY CreatedOn DESC, SheetID DESC`，试验单页与历史页共用
  —— 两处顺序一致。`CreatedOn` 是 `yyyy-MM-dd HH:mm:ss` 定长文本，文本序 = 时间序。

## 曲线标注（用户 2026-10-13）

- **时机**：只在该试件**完成后**标注（过程中不画）；新一轮开始随曲线一起清掉。
- **四处内容**：

  | 标注 | 画法 | 取值 |
  | --- | --- | --- |
  | 峰值点 | 橙红实心圆 + 文字 `峰值 {荷载} kN / {挠度} mm` | 曲线里荷载最大的点 |
  | 修正直线 y = k·x + b | 主题文字色**虚线**，横跨整条曲线、下端交 X 轴 | 判定器拟合结果 |
  | 修正原点 | 空心圆 + 文字 `修正原点 {x} mm` | 直线与 X 轴交点 |
  | 拟合区间两端 | 空心圆 + 文字 `{百分比}% {荷载} kN`，**标在曲线上** | 曲线**上升段**与该荷载的交点（线性插值，`CurveDisplay.PointAtLoad`） |

  > 拟合区间两端这两点画在**实测曲线上**（它们是拟合区间的上下沿），**不是**画在修正直线上
  > —— 用户 2026-10-13 当天更正。曲线上升段没经过该荷载时（异常数据）才回落到修正直线上求交点。

- **量程口径**：**先 `AutoScale()`，再画标注**，标注**不参与**自动量程
  —— 修正直线在曲线尾部的延长值远高于峰值，参与量程会把曲线压扁。
- **两页共用** `Charts\CurveAnnotator.Draw`（试验执行页 + 历史数据页），两处必然一致；
  标注墨色取主题文字色 `CurveChartTheme.AnnotationColor()`，所以**换主题/换语言要整幅重画一次**。
- 参数表「启用曲线原点修正」**关掉就不画**直线与交点（判定器 `TangentK` = 0 → `CurveAnnotation.HasFit` 为 false），
  只留峰值点。
- **曲线首点按定义记在位移零点**（X = 0）：接触那一帧就是位移零点（现役同口径 `ActualDeformation := 0`）。
  2026-10-13 之前的库把首点记成了调零前的位移，回放时用 `CurveDisplay.ZeroFirstPointX` **只在显示上**抹平；
  库里与报表都用原始序列。
- 历史页与执行页的曲线都走同一套**显示抽稀 + 节流**口径（`CurveDownsampler`，绘图区像素宽 × 2 点封顶）。

## 导航栏（用户 2026-10-13）

- **折叠时鼠标悬停要能看到该项文字提示；展开时不弹**（展开时项上本来就有文字，气泡是多余的）。
- 做法：`NavigationView.IsPaneOpen` **双向绑定**到 `ShellViewModel.IsPaneOpen`；`OnIsPaneOpenChanged`
  与 `RebuildNavigation()` 末尾都调 `UpdateNavigationToolTips()` —— 折叠时把每项的 `ToolTip`
  设成 `Content`（当前语言的导航名），展开时清空。换语言会重建导航项，提示跟着换语言重新挂。
- **WPF-UI 自己不给折叠项挂提示**（实测：折叠后悬停无任何气泡）——这是本工程补的行为。
  以后加导航项**不用单独处理**，统一走 `UpdateNavigationToolTips()`。
- **进「试验执行」页自动收起导航栏**（用户 2026-10-14）：那一页控件多、要宽度。
  实现：页面不直接摸外壳控件 —— 外壳（`ShellViewModel`，也是 `INavigationPaneService` 的实现者）
  持有 `IsPaneOpen`，`TestExecutionViewModel.OnNavigatedTo()` 调 `Collapse()`。
  收起后导航项只剩图标，悬停提示由上面那套自动挂上；用户点折叠按钮仍可随时展开，换页不会自动展开。

## 弹出窗体（用户 2026-10-13）

- 以下三页以**模态弹窗**打开（不再换掉内容区）：**试验参数**（机器与控制参数）、
  **试验单**（新建试验单 / 选择已有试验单）、**试样信息填录**（新建试样 / 编辑试样）。
  入口都在试验执行页的按钮上。
- 弹窗外观：`Views\Dialogs\PageDialogWindow`（`FluentWindow` + `TitleBar` 只留"拖动 + 关闭 X"，
  无最大化/最小化）；**不重复写标题**，页面自己的大标题就是弹窗标题。
- 机制：`Services\ModalPageService.cs` 的 `IModalPageService.Show(pageType, width, height)`
  —— 从 DI 取页面 → 装进窗口 → `ShowDialog()`；返回 `true` = 页面给了「确定」。
- **页面只能用 `Frame`（或直接作 Window 内容）承接**：WPF 的 `Page` 只允许 Window / Frame 当父级，
  放进普通 `ContentPresenter` 会运行期抛"Page 只能具有 Window 或 Frame 父级"（已踩）。
- 页面 ↔ 宿主的对话：ViewModel 发 `IModalDialogViewModel.CloseRequested`；页面实现 `IModalPage`
  把事件转发出来（页面的 `DataContext` 是自己，宿主拿不到 ViewModel）；窗口据此设 `DialogResult`。
  **关窗时必须退订**（`Closed` 事件 + 关窗前各退一次）：ViewModel 是单例，不退订会在**第二次**弹窗关闭时
  对已关闭的窗口设 `DialogResult`，抛"只能在创建 Window 并且作为对话框显示之后才能设置 DialogResult"（已踩）。
- **弹窗不触发 `OnNavigatedTo`**：数据刷新统一走 `ViewModelBase.OnOpened()`（导航与弹窗两条路都会调），
  页面实现 `IModalPage.OnDialogOpened()` 转调它。参数页 / 试验单页都已改用 `OnOpened`。
- 尺寸按内容定：参数弹窗 **1340×800**（要并排放运行期 / 计算期两张 620 宽的卡，窄了 WrapPanel 会换行）；
  试验单弹窗 **880×780**（字段区两列 10 行 + "其他试验项目"的已有单列表，2026-10-14 改）；
  试样信息填录弹窗 **1060×620**。
- 参数页与试样页底部都补了「关闭」按钮（文案用 `Common.Close`；以前靠导航栏离开，弹窗里没有导航栏）。

## 配置文件与系统设置持久化（用户 2026-10-14）

- **约定：程序目录下的 `Config\` 放所有配置文件**（首次启动自动创建）。
  与产物目录 `Bins\`（库在 `Bins\Data\anx.db`、报表与曲线图在 `Bins\Report`）分开：
  一个是"人可以改的配置"，一个是"程序产出的数据"。
- 第一个文件：`Config\settings.json`（键值表，对应 `ANX.Core.Settings.AppSettingKeys`）——
  目前是 `system.language` 与 `system.theme`，可直接用记事本改。
- **为什么设置不放库里**：① 语言与主题必须在**读库之前**拿到 —— 连"库架构版本不匹配、
  请备份后重建"那个提示框都要用用户选的语言显示；② 塞进库会牵动架构版本校验（加表/列要走迁移，
  还会让用户现有的库撞上"版本不匹配"拦截）。界面偏好不该有这种代价。
- 启动顺序：`OnStartup` **先**读配置文件应用语言/主题 → **再**建库/校验版本。
  配置文件缺失、键缺失、值不认得（手工改错）一律**回默认值继续启动**（zh-CN / Dark）并记一条日志。
- 设置页是"改了立即生效 + 立即落盘"（没有确定/取消按钮），所以底部加了一行状态：
  成功显示"已写入配置文件（下次启动仍然生效）"，失败走**红字闪烁**（复用 `StatusTextStyle`）。

> 实体：`ANX.Storage.FileAppSettingsService`（外部文件实现）、`ANX.Host.AppPaths`（路径约定）、
> `SettingsViewModel`（改了就落盘）。实现要点：整份读进内存、写盘"临时文件 + 原子替换"、
> 读坏了不抛异常（坏文件下一次写入自然覆盖）、写失败照实抛出交给界面显示。

### 操控信息列表：超长行悬停看全文（用户 2026-10-14）

操控信息那栏宽度有限，长行以前被**直接裁掉**（看不出被截断）。现在给 ListBox 加了 ItemTemplate：

- `TextTrimming="CharacterEllipsis"` —— 超长显示 `…`，一眼能看出还有内容；
- `ToolTip="{Binding}"` —— 鼠标悬停弹出**完整文本**（ToolTip 绑的是条目自身，日志条目是字符串）。

**已知取舍**：短行悬停也会弹一个等长提示（无害但略冗余）。
要做到"只在真被截断时才弹"，需要自写 attached property：用 `FormattedText` 按当前字体量出文本宽度，
和 `ActualWidth` 比一下，超了才赋 ToolTip。属可选优化，日志条目基本都很长，暂不做。

### 断链时的行为（用户 2026-10-14 真机联调后定稿）

| 场景 | 界面与动作 |
| --- | --- |
| 链路断开（待机中） | 状态栏红字 `链路断开 · <网卡>`；「启动试验」与工作台升降**置灰**；**实时读数卡片三张标 `--`**；弹**待机版**报警 |
| 链路断开（试验中） | 同上置灰 + 卡片刻 `--`；弹**试验中版**报警（说清"这一轮已被中止、已尽力发停止但无法确认"）；控制循环 2 秒后按 `CommunicationLost` 收尾 |
| 链路恢复 | 状态栏恢复；按钮恢复可用；**实时卡自动恢复实时值**；**不自动重连、不自动续跑**，需人工确认 |

- **停机闭环确认**：发停止 ≠ 停住。`MotorStopConfirmation.WaitStoppedAsync` 等状态回帧里的电机位
  （`IsMotorRunning == false`）最多 2 秒，等不到就如实报「停机未确认」。
  判据只能是状态回帧 —— 实测链路断开、甚至**没有路由**时，UDP 的 `Send` 照样返回成功。
  一次收尾**只报一条**：停止命令本身发失败时不再等确认（结论已明确），只把原因附在后面
  （原先会连出 3 条近似消息：尽力停止失败 / 停止命令失败 / 确认超时）。
- **断链时"尽力发一次停止"** 只是尽力而为（`Exec.LinkStopBestEffort`），**不当安全保障**：
  命令可能根本没出去。真正能停住设备的是下位机自己的看门狗（实测 60 秒会话超时）与硬件限位。
- **报警弹窗规则（用户 2026-10-14 定稿）**：**只有"试验正在跑"时断链才弹**
  （待机断链没有设备动作被打断，弹窗只会打断操作；现场网线会抖，待机也弹就成了骚扰 ——
  待机的情况留状态栏红字 + 操控信息 + 日志）；
  同一断链只弹一次（节流 1 分钟）；**开机时线就没插过不弹**（那是常态）。
  文案只有"试验被打断"那一版（已中止 / 已尽力发停止但无法确认 / 请立即到现场）。
- **实时卡标 `--` 只标三张实时卡**（荷载 / 位移 / 试验持续时间）：
  「弯拉强度 / 修正原点 / 应变 / 挠度」与峰值是**结果**，标掉等于把上一轮成果从界面抹了。
  链路断着时还要**停止往卡片写值**（`UpdateCards` 里判链路），否则在途那一帧会把 `--` 覆盖回旧值。

> **⚠ 两条踩过的坑（都在 UI 线程上炸过）**
> 1. `finally` 里**裸 `await device.StopAsync()`**：链路断时它要等 A1 应答、3 秒后抛超时，
>    异常从 finally 抛出 → 后面的 `IsRunning = false` / 令牌释放全没执行 → 界面**永远停在"运行中"**，
>    按钮一直显示「停止试验」，再点只打日志。**收尾里每一步都要自己 try/catch**；
>    顺序保持"先发停止、再复位状态"（复位太早会让用户在收尾那几秒里又点启动，两条流程抢同一个 CTS）。
> 2. UI 上下文的 async 方法里写了 **`.ConfigureAwait(false)`**：之后 `PhaseText = …`、`Append(…)`
>    跑到线程池线程上，改了绑在 ListBox 上的 `ObservableCollection` →
>    `InvalidOperationException：某个 ItemsControl 与它的项源不一致`（累积 13 项 vs 实际 14 项）。
>    `Append` 现在自带线程兜底（不在 UI 线程就转投），但**别在 UI 方法里再用 `.ConfigureAwait(false)`**。

- **为什么要自己看链路**：上位机与控制器走 **UDP**（`UdpChannel`：`SocketType.Dgram` + `Connect` 远端），
  UDP 无连接 —— 拔网线**不会**报任何 socket 错误，收发循环只是"再也没有数据"。
  在此之前 `IsConnected` 只是"曾经收到过 A0"的闩锁，拔了线界面仍显示"已连接"（绿色），比报错更危险。
- **实现**：`ANX.Core.Control.INetworkLinkMonitor`（契约，放在设备契约旁边，UI 不必引用传输层）
  + `ANX.Communication.NetworkLink.NetworkLinkMonitor`（实现）。
  定位网卡：记住上次那块网卡的 Id → **同网段匹配**（设备就在直连网段上；网线刚拔时网卡还留着旧地址，
  照样认得出来）→ 路由探针（`UDP Connect` 只问路由表，给"设备在别的网段"兜底）。
  **不要用"只有一块以太网卡就认它"**：本机枚举到 WFP/QoS 等过滤驱动也报 `Ethernet` 且 Up，会认到假网卡上。
  触发方式：**2 秒轮询为主**（Windows 的网卡事件会合并/丢），`NetworkChange` 事件只作加速。
- **变化判定只认"链路类别 + 网卡名"**，不认 `Detail`：`Detail` 里带协商速率，
  实测 WLAN 在 156/173.3 Mbps 之间来回跳，按整条记录比会把速率抖动当成链路变化（日志与操控信息被灌满）。
- **界面**：状态栏「连接状态」在链路断时**优先报链路**（红字 `链路断开 · <网卡>`），
  因为这时"已连接"是假象；操控信息里追加一条带原因的记录；链路变化另外落 Serilog（现场事后可查）。
- 日志/自检要用到的两个环境变量：`ANX_DEVICE_HOST`（顶掉控制器地址）、`ANX_USE_SIMULATOR=1`（模拟器，
  此时**不注册**链路监视器 —— 假设备报真网线断了只是噪音）。
- **当前只报不拦**：跑试验中链路断了，界面会报但**不打断试验**（是否停机属另一条口径，待用户定）。

- **行序（自上而下，用户 2026-10-13 定）**：① 试验单号行 → ② 试样按钮行（新建 / 编辑 / 删除试样）
  → ③ 试样信息列表（`*` 行）→ ④ 底部（启动/停止 + 运行指示框 + 有效性计算）。

    弯曲是 试件号 + 跨径 L / 试件宽度 b / 试件高度 h），所以列在 code-behind 里建（`BuildSampleColumns`），

- **按钮可用性**（用户 2026-10-13，同日修订四次；最后一条是"任何时候不要自动新建试样信息"）：

- **任何时候都不要自动新建试样信息**（用户 2026-10-13）：启动试验**只跑列表里选中的那一件**，
  没选中就不启动（操控信息里提示"请先在试样信息列表里选中要做的试样"），**不替用户建**。
  连带地，「新建试样」的可用性不能再看"列表非空"——否则新单里第一件没处建（原先那个死结就是这么来的）。
- **「有效性计算」按钮的可用性**（用户 2026-10-13）：**有当前单** && **至少三件"有判定值"的试样**
  （依据 T 0715-2025 5.6：一组不少于 3 个试件）&& **没在跑试验**。
  - **算完之后**若剔除后有效件**不足 3 件**：写一行日志 + **弹提示框**
    （"剔除后有效试件 N 个（少于 3 个），按规范 5.6 应补充试验。"），并且**本次不写组结果**
    —— 主表均值列写空（连上一次的旧均值一起清掉），只写件数与"需补做"标志。
    与现役一致（`uBendingTestForm.pas:620-623`：日志 + `UWPInfoMessage`，"本次不写组结果"）。
  - **与"选中哪一行"无关** —— 它是**整单**操作（读该单所有明细算组统计）。
    现役同口径：`btnCalcResult.Enabled := not (DataSet.IsEmpty)`（`uBendingTestForm.pas:1312`）。
  - 判据用**有没有判定值**（弯拉强度与最大弯拉应变都读得出来），**不是**明细行的状态列 ——
    状态列可能是"没写"，判定值才是"真算出来了"（2026-10-13 的老数据事故就是这个区别）。
  - 单号走**当前单**口径（`CurrentSheetId`：优先试验单弹窗里选定的单，其次自动建的那张），
    与列表/单号显示同源，避免"列表是 A 单、算的是 B 单"。
  - 与"单是否已完成""是否联机""是否已经算过"**无关**（重算就是修数据，幂等、可重复点）。
  - 计算中不需要额外开关：命令是异步的，CommunityToolkit 默认不允许并发执行，点击期间按钮自动不可用。
  "完成试验"= 明细行 `TestStatus` = **2**（现役枚举 `tsNotTested=0, tsTesting=1, tsCompleted=2, tsFailed=3`），
  试件跑完判定落库时写入（`BendingExecution`）。**老数据这一列是空的 → 不算完成**，仍可编辑。
- **删除试样**（用户 2026-10-13 要求真做）：先弹确认框（提示曲线 / 判定值 / 试样信息一起删、不能撤销），
  确认后按 `(SheetID, SampleID)` 删明细行（现役 `DeleteRecord(SheetID, SampleID)` 同口径），再刷新列表。
  删不存在的件不报错、只记一行"没找到这件试样"。
- **编辑试样 = 编辑选中那件**（选中哪件改哪件）；新建试样 = 弹窗自带下一个试件号；
  删除试样 = 删选中那件。
- **启动试验 = 跑列表里选中的那件**（用户 2026-10-13）：**没选中就不给启动**，也不会自动建新件。
  判定落库是"有则更新、无则追加"，所以重跑一件**未完成**的试样会**覆盖它原有的曲线与结果**；
  已完成的件不给跑（启动按钮置灰）。
  ⚠ 实现上要在**刷新列表之前**把选中件号取下来 —— 刷新列表会清空选中项，
  取晚了就退化成"新建下一件"（2026-10-13 实测踩到：选了 3 却跑出 S028）。

### 三种试验方式（照现役 `uEditBendingTestForm`）

**每次打开弹窗都以「新建试验项目」起步**（用户 2026-10-14）：ViewModel 是单例，
不复位的话下次打开会停在用户上次选的"其他试验项目"上，还带着上次那张单的信息。
复位在 `InitializeAsync()` 里做（`Mode = New` + 丢掉上次选中的 `SelectedSheet`），
期间用 `_resettingMode` 挡住按模式载入，避免和随后那次 `LoadForModeAsync()` 并发抢着填表。

| 方式 | 单号 | 字段 | 点「确定」做什么 | 什么时候可选 |
| --- | --- | --- | --- | --- |
| 新建试验项目 | 自动生成（显示的是**预览号**，确定时才真正发号） | **可编辑**，必填项照现役校验 | 新建一张单 + 把单上的加载速率写回参数表 | 总是可选 |
| 上次试验项目 | 沿用那单的号，只读 | **整页只读** | 采用"上一次新建的那张单"（不新建、不动库） | 试验信息表**为空时置灰** |
| 其他试验项目 | 沿用所选单的号，只读 | **可编辑** | **把改动写回该单**（= 改已有单信息的入口）+ 加载速率写回参数表 | 总是可选 |

只读的落地方式照现役 `SetControlsReadonly`：文本框 `IsReadOnly`、**下拉框 / 日期框整只 `IsEnabled=False`**
（它们没有"只读"这一说）。**单号与试验时间在任何模式下都只读**：单号是主键、试验时间是该单的原始记录，
写回时会把这俩键剔掉（用户 2026-10-14）。

### 字段区版面（照现役，用户 2026-10-14：控件排列按照现役软件中的次序）

现役是一个**两列网格、按行配对**（左列工程与试验条件、右列体积指标 6 项 + 接样日期 / 试验时间 / 试验员）。

监理单位       | 沥青用量           项目名称 *     | 沥青体积百分比
