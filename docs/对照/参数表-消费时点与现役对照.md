# 试验参数表：两类消费时点，与现役字段对照（2026-10-12）

用户提出：现役参数表的字段"要么在试验过程中起作用，要么在试验完成后的计算过程起作用"，
ANX 要能同样做到。本文件记录我们的两个消费点、与现役 26 列的逐项对照，以及本轮补齐的三项能力。

## 1. 两个消费时点（ANX）

| 时点 | 代码位置 | 参数如何生效 |
| --- | --- | --- |
| **运行期** | `ITestExecution.LoadProfileAsync()` → `TestRunProfile` → 控制循环 / `TestSequencer` | 每次"开始试验"前重读，装配接触阈值 / 破坏判据 / 确认帧数 / 试验速率 / 平台升降速率 / 两个闸门系数 |
| **计算期** | `ITestExecution.CompleteSampleAsync()` → `BendingAnalyzer.Analyze(...)`；以及 `RecomputeSheetAsync()`（重算） | 每次判定时重读跨径 / 试件宽高 / 是否原点修正，算出强度、应变、校正挠度、修正原点 |

共同点：**运行时读一次、判定时再读一次**；参数改动对"下一次开始"和"下一次判定/重算"生效，
正在跑的那一轮不中途变参数（与现役"线程启动时装配、结算时再取一次"同构）。

## 2. 现役 `TestParameterConfig` 26 列的对照

现役是**所有方法共用一张超集表**，每个方法的窗体只挑自己要的列装配（`uBendingTestForm.pas` 1547-1565
只用了 5 列；`NotDetermineFragmentationPoint`、`LockDisplacement`、`ContinueLoadingTime`、
`DataRecording*`、`DisplayBy*` 等在弯曲线程里出现 0 次）。ANX 是**每个方法自己声明参数清单**，
不会出现"表里有列但没人用"。

| 现役列 | 时点 | ANX 现状 |
| --- | --- | --- |
| `MachineSpeed` | 运行期（试验速率） | ✅ `LoadRate` |
| `ZeroDisplacement` | 运行期（接触阈值，N→kN） | ✅ `ContactLoad` |
| `PressureDrop` | 运行期（破坏落差） | ✅ `BreakDrop` |
| `NumberOfFilters` | 运行期（当"破坏确认帧数"用） | ✅ `BreakConfirmSamples` |
| `AutoFallTime` | 运行期（破坏后回缩/自动复位秒数） | ⚠️ 方法常量 `ResetSeconds = 5`（未进参数表） |
| `OriginCorrectionStart` / `End` | **计算期**（原点修正拟合区间） | ⚠️ 常量 10%~80%（`FallbackStartPercent/EndPercent`） |
| `EnableOriginCorrection` | **计算期开关** | ✅ 本轮加 `EnableOriginCorrection`（默认 1；现役那边写死 True，实际没有开关效果） |
| `LockDisplacement` | 计算期（峰值位移锁定口径） | ❌ 未实现 |
| `NotDetermineFragmentationPoint` | 运行期（弱荷载不判破碎下限） | ❌ 未实现 |
| `ContinueLoadingTime` | 运行期（破碎后继续加载） | ❌ 未实现 |
| `AxialPressureChannel` / `AxialDisplacementChannel` / `HorizontalDisplacementChannel` | 采集口径 | ⚠️ 硬编码（压力索引 0 / 位移索引 1，见冲突表条目 17） |
| `EnableDualSensors` | 采集口径 | ❌ 未实现（现役弯曲取位移通道 1+2 平均） |
| `EnableReverseDirectionOfForce` / `EnableBreakagePointJudgmentByHost` | 运行期策略 | ❌ 未实现 |
| `DataRecordingMethod` / `StartingPointOfDataRecording` / `DataRecordingInterval` | 记录策略 | ❌ 未实现（曲线固定按接触后全记） |
| `DataFlowDisplayMode` / `DisplayByPressureInterval` / `DisplayByDisplacementInterval` / `DisplayByTimeInterval` | 界面显示抽样 | ❌ 未实现（执行页按固定 50Hz 节流刷新） |
| `AsphaltTestTypeID` / `ConfigMode` | 表结构键 | ➖ 等价物是 `MethodCode`（ANX 无 ConfigMode，单套配置） |

## 3. 本轮补齐（2026-10-12）

1. **`EnableOriginCorrection`（计算期开关，默认启用）** —— 用户："有的试验需要，有的不需要"。
   关闭时不拟合修正直线：修正原点记 0、校正挠度 = 峰值挠度、应变按未修正挠度算
   （`BendingAnalyzer.Analyze(..., enableOriginCorrection: false)`）。
2. **两个速率** —— 用户："加载速率要两个，一个控制平台升降、一个用于试验过程"。
   `JogSpeed`（平台升降，执行页"工作台上升/下降"按钮用，默认 50mm/min）与 `LoadRate`（试验过程，默认 50）
   彻底分开；执行页每次按下按钮时按参数表当前值走，仍受**电机上限 50mm/min** 截断。
   （另有一个"接近段速率" `ApproachSpeed` 仍是方法常量 10mm/min，与现役 `CONTACT_SPEED_MM_MIN` 同值 —— 现役也是三个速率。）
3. **"按当前参数重算"入口** —— 用户要求。历史数据页新增按钮：对选中试验单的**所有已存曲线**
   按当前参数重新判定，覆盖明细结果列与组统计（曲线本身不动；单件判定不了只跳过、不连累整单），
   点击前有二次确认，完成后状态栏报"已重算 N 件、跳过 M 件"。

## 4. 边界

- 重算**不会**自动发生：改参数只影响之后的判定与重算，已存结果要显式点"按当前参数重算"。
- 重算是**覆盖写**（明细结果列 + 主表组统计），曲线保留；因此入口做了二次确认。
- 重算与运行结算共用同一份口径（`LoadAnalysisParametersAsync` + `BuildResultColumns`），
  避免"跑出来"和"算出来"两套算法。
