## 已核对通过的部分（M2）

- **CRC-8 表**：ANX 的 `Gr3Crc8.Table` 与现役 `UdpClientEx.pas` 的 `CRCTable` 字面量 **256/256 项一致**（测试 `Gr3Crc8Tests`）。
- **帧布局**：外层与内层结构与文档第一、二章逐字节一致；A1 应答帧与文档 2.2 节的举例 `EE EE EE 0B 00 01 FA FB FC 03 A1 …` **前 11 字节完全对上**（测试 `Gr3FrameCodecTests`）。
- **下行字段**：C0（年月日时分秒 + Int32 密钥）、C2（14 字节 ASCII）、C4（方向 + UInt16 速度）、CA（order=2 读设备 ID）、CB（order=1）与文档第三章一致。

## 仍未闭环的两条

2. **条目 7**：含 Int32 的帧是否确实大端。

## 真机抓帧结果（2026-10-10，实体 GR-3 @ 192.168.0.122:5001）

用 ANX 自己的只读探针（`tools\ANX.Tools.Gr3Probe`：只发 C0 联机 / CB 心跳 / CAH 读设备 ID / CAH 读通道配置）**联机成功**。
原始抓帧：`docs\抓帧\gr3-20261010-140424.log`；黄金夹具：`tests\ANX.Protocol.Tests\Gr3\Frames\gr3-live-20261010.hex.txt`；
回归测试：`Gr3LiveFrameTests`（真机帧若与 ANX 的帧长度 / CRC / 校验和 / 命令字任一处不符，解码就会失败）。

上面「仍未闭环的两条」**均已闭环**，另修正一条：

- **条目 4 闭环**：联机后 **A0 会自动推**（70 B 帧 / 数据域 56 B），**A4 不自动推** —— 必须用 CAH(order=2) 主动读。文档「首先返回 A0 和 A4」只对了一半。
- **条目 7 闭环**：C0 的 Int32 密钥**按大端**发出即被设备接受（随后自动回 A0 并以约 190Hz 推 A2，说明合法性验证通过）。文档那句「按 union 存储顺序」与实际不符。
- **条目 11 闭环**：实测每个数据报**打包 5 帧**（425 B = 5 × 85 B），且**包编号逐帧递增**（00 02 → 00 06）。
- **条目 5 修正**：实测约 **190Hz**（约 6 秒内收到 1130 帧 A2 ≈ 5.3ms 一帧），**不是**文档写的 120Hz。M3 的容量估算按 ~190Hz / 每帧 85 B 来。

## M3 补充：上行数据域（2026-10-10，真机）

M3 第一步做 A0 / A2 / A3 的上行解析。数据域长度与字段顺序全部与真机对上，另外发现两条文档问题：

| # | 位置 | 文档怎么说 | 真机怎么做 | 裁决 |
| --- | --- | --- | --- | --- |
| 14 | A3H 的格式行 | 2.4 节写着「命令：**0xA2**」，而同一节的字段表写「命令类型 = 0xA3」 | 真机回的是 **0xA3** | **按 0xA3**；格式行里的 0xA2 是笔误 |
| 15 | A3H 的通道号取值 | 「模拟通道号，取值：**1-12**」 | 请求通道 **0**（越界）时设备**不报错**，回一帧「通道号 / 量程 / 小数位 / 量纲全 0」的配置帧，标定段是未定义内容 | **通道号从 1 起用**；越界不报错 → 校验得由应用层自己做 |

**A3 实测（通道 1，两帧都在夹具里）**：`Channel=1`、`Range=1000`、`Digital=2`、`Unit=1`（载荷 kN），
标定实值 `9900 → 100000`（11 点递增）、标定码值 `100 → 10000`（11 点递增）。

**由此反推出换算口径**：`工程量 = raw / 10^Digital`。因为 `Digital=2` 时标定实值 `9900 → 99.00`、
`100000 → 1000.00`，正好等于 `Range=1000`（满量程）—— 这条在两个实现里都没写明，是**从标定表倒推出来**的，
已写进 `ANX.Protocol.Gr3.Gr3ChannelConfig.ToEngineeringValue`。

**A0 实测（56 B）**：硬件版本 10 / 固件 15 / 协议 10；压力通道量程 `1000 / 100 / 300 / 0`；压力小数位 `2 / 2 / 3 / 0`；
压力量纲 `1 / 0 / 3 / 0`；围压有效位 1。

**A2 实测（71 B / 帧）**：压力四通道 `0 / 100 / -1 / 0`（`-1 = 0xFFFFFFFF` 表示未接通道）；
机器状态 `0x12`、试验状态 `0x00`、端口输出 B `0x0000`、端口输入 A `0x00`、端口输入 B `0x0102`；温度与扩展引伸计均为 0。

**状态位定义（已落地）**：协议文档 2.3 节给出了位定义 —— 机器状态 Bit0 压力过载 / Bit1 位移上限位 / Bit2 位移下限位 /
Bit3 电机正转（上升）运行 / Bit4 电机反转（下降）运行 / Bit5 控温；试验状态 Bit0 试验运行中 / Bit1 试验暂停中 /
Bit2 破碎点已找到 / Bit3 稳压（保持）中。与参考实现（ICC）的解读一致，已包成 `Gr3MachineStatus` / `Gr3TestStatus`
并用单元测试逐位锁住。真机的 `0x12` 即「位移上限位 + 电机反转（下降）运行中」。
**端口状态**（PortOutputB / PortInputA / PortInputB）的位定义文档里没有，仍按原始值暴露。
